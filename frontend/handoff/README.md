# GS Labs Monitoring — инженерный handoff

Этот пакет описывает переход от текущего UI-прототипа к production-системе мониторинга новостей и нормативно-правовых актов (НПА).

## Что передаётся

| Материал | Назначение |
| --- | --- |
| `01-product-and-ui.md` | Пользовательские сценарии, правила экранов и состояние текущего UI. |
| `02-target-architecture.md` | Рекомендуемая архитектура, границы сервисов и фоновые процессы. |
| `03-data-model.md` | Реляционная модель, сущности, статусы и связи. |
| `04-api-contract.md` | HTTP API для фронтенда и интеграций. |
| `05-processing-pipeline.md` | Загрузка источников, извлечение, дедупликация, LLM-обработка и проверка НПА. |
| `06-delivery-plan.md` | Порядок внедрения, миграция UI и критерии готовности. |
| `openapi.yaml` | Черновая спецификация контрактов для старта backend-разработки. |

## Текущий репозиторий

`gs-labs-monitoring-ui` — React 19 + TypeScript + Vite 8 + Tailwind v4 + shadcn/ui (Base UI/Rhea) + React Router + Lucide.

Маршруты:

- `/news` — входящие новости;
- `/npa` — реестр отслеживаемых НПА, алерты и изменения;
- `/sources` — активные источники.

Текущие данные находятся в `src/data/`; они демонстрационные. Действия сохраняются только в `sessionStorage` через `src/hooks/useSessionState.ts`. При подключении API этот механизм нужно заменить серверным состоянием и query-кэшем.

## Как читать пакет

1. Product/UX и текущие границы — `01-product-and-ui.md`.
2. Backend, БД и пайплайны — `02–05`.
3. План работ и приёмка — `06-delivery-plan.md`.

## Важная граница MVP

UI не должен самостоятельно выполнять парсинг, хранить реальные документы, запускать LLM или обращаться к сайтам источников. Он получает готовые нормализованные сущности и статусы задач по API. Любая загруженная PDF или ссылка сначала попадает в безопасное хранилище и очередь обработки.
