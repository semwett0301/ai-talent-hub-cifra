# 01. Продуктовая логика и UI

## Роли

- **Аналитик PR/GR** читает входящие материалы, скрывает шум, вручную уточняет AI-саммари.
- **Владелец направления** формирует реестр важных НПА, смотрит изменения и их влияние.
- **Администратор** подключает источники и задаёт частоту их проверки.
- **Система** собирает публикации, определяет релевантность, находит НПА-сигналы и отслеживает новые версии документов.

## News: `/news`

Лента содержит нормализованные новости. По умолчанию список сортируется по `relevance_score DESC`, но числовой score пользователю не показывается.

Категории отображения:

| Score | Метка |
| --- | --- |
| 0–49 | Шум |
| 50–64 | Релевантно |
| 65–79 | Важно |
| 80–100 | Горячая новость |

Фильтры: «Все», «Требует внимания», «Новости»; период: 24 часа или 3 дня; полнотекстовый поиск по заголовку, источнику, тегам и содержимому. Материалы со статусом `hidden` не входят в выдачу. Кнопка «Вернуть скрытые» снимает статус для текущего пользователя.

При выборе новости справа показываются источник, время, AI-саммари и «Почему это важно для GS Labs». Доступны действия:

- **Редактировать** — создаёт пользовательскую редакцию саммари, не изменяя исходный результат модели;
- **Скрыть** — скрывает материал только для пользователя или команды, в зависимости от выбранной серверной политики.

## NPA: `/npa`

Три режима:

1. **Реестр отслеживаемых НПА** — документы, которые команда добавила для наблюдения.
2. **Алерты** — новости или сигналы о готовящихся законах и изменениях в НПА. Детали повторяют паттерн News, плюс есть «Добавить закон вручную».
3. **Обновления НПА** — подмножество реестра, у которого есть непроработанные изменения после последней успешной проверки.

В деталях НПА:

- список изменённых статей; при клике — короткое LLM-пояснение изменения;
- «Изменений нет», если сравнение версий не выявило содержательных правок;
- общий вывод LLM;
- влияние на GS Labs: риск, затронутые процессы и рекомендуемые действия.

Добавление НПА выполняется одним из способов: публичная HTTPS-ссылка или PDF-файл. В одном запросе допустим только один способ.

## Sources: `/sources`

Каждая строка — источник с типом, адресом, частотой и флагом отслеживания. Переключатель `enabled=false` останавливает будущие задачи сбора, но не удаляет исторические материалы.

Допустимые частоты: `30m`, `1h`, `3h`, `8h`, `24h`, `3d`, `1w`, `1mo`, `1q`. В интерфейсе они локализуются: «каждые 30 мин», «каждый час» и т. д. Новый источник проверяется до сохранения: URL, тип и дубликат.

## Общее поведение

- В продуктивной версии все действия должны быть оптимистичными только при наличии идемпотентного API и отката при ошибке.
- UI должен показывать `loading`, `empty`, `error` и время последней проверки там, где данные асинхронны.
- Все показанные даты должны приходить как ISO 8601 UTC; локализацию выполняет клиент.
